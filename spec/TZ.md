## 2. Принципы продукта (неизменяемые решения)

1. **Local-first.** Все данные хранятся локально в браузере (IndexedDB). Приложение полностью работает офлайн. Регистрация/аккаунт не требуются.
2. **PWA.** Устанавливается на домашний экран, работает как нативное: офлайн-режим, иконка, отдельное окно. Один код для iOS/Android/десктопа.
3. **Одна встроенная программа.** Схема выбрана по результатам научного deep research (З1): **синтез** — тест → якорь → цикл 6 шагов × 5 подходов с финальным «Максимум (минимум N)». Полная спецификация в §3.2.1 и в `research/research-pullup-program-science-2026-08-15.md`.
4. **Адаптивность к уровню.** Входной тест на максимум подтягиваний → программа подбирает стартовый шаг. Не выполнил план — программа не продвигает дальше (повтор шага), выполнил — идёт вперёд.
5. **Научно обоснованные дефолты.** Таймер отдыха: дефолт 3 мин, пресеты 90 с (гипертрофия) и 5 мин (тяжёлые подходы) — всё настраивается. Программа строится на принципах с доказательной базой (частота 2–3 р/нед, прогрессивная перегрузка, объём ≥10 сетов/нед — наша схема даёт 5 подходов × 3 тренировки = 15, периодический ретест).
6. **Полностью бесплатно и без рекламы** — навсегда.
7. **Без аудио.** Никаких звуков и голосовых подсказок. Сигналы окончания отдыха — вибрация + системное уведомление.
8. **Mobile-first.** Приоритет — мобильные устройства; десктоп просто должен открываться и корректно работать (специальных десктоп-удобств не делаем).
9. **Единая дизайн-система Poster / Swiss.** Плоские поверхности, 2px рамки, офсетные тени, гигантская типографика, без градиентов/блюра/эмодзи. Все стили — только через токены `design/theme-tokens.css`; компоненты собственные (без UI-библиотеки).
10. **Научная прозрачность.** Пользователь может в любой момент открыть страницу «Почему программа такая» (§3.10) и увидеть полное обоснование: на каких исследованиях построена схема и все формулы. Ссылаемся только на открытые источники.

## 3. Функциональные требования

### 3.1 Модель данных и базовые понятия

- **Программа** — упорядоченный список тренировок (шагов). В приложении одна встроенная программа.
- **Тренировка (шаг)** — список подходов. Активные типы подходов программы: «повторения», «максимум». Типы «удержание», «негатив», «ассист» допустимы только в legacy-записях истории (read-only).
- **Тест** — тренировка-измерение максимума повторений, по результату которой выбирается стартовый шаг программы (якорь).
- **Запись о выполнении** — результат прохождения тренировки: фактические повторения по подходам, отметка успех/провал, дата, длительность. История тренировок глобальна и **не привязана к программам**.
- **Прогресс программы** — текущий шаг и расписание встроенной программы; хранится отдельно от глобальной истории/статистики.

### 3.2 Программы

#### 3.2.1 Встроенная программа (единственная) — зафиксировано по З1

**Итог З1: синтез, а не существующая программа.** Обоснование и 53 источника — в `research/research-pullup-program-science-2026-08-15.md`. Ключевой отрицательный результат: прямых РКИ по схемам прогрессии в подтягиваниях не существует — схема собрана из непрямой научной базы (частота, объём, отдых, близость к отказу, авторегуляция).

**Вход и уровни:**
- Тест максимума строгих подтягиваний до отказа → результат M (якорь). **Минимально допустимое M = 1.** Если пользователь не может подтянуться ни разу — приложение ему пока не подходит; вернуться после первого подтягивания.
- Уровни (только метка, шаги генерируются правилом): 1–4 → L1 «Новичок»; 5–9 → L2 «База»; 10–19 → L3 «Средний»; 20+ → L4 «Продвинутый».

**Генеративное правило шагов (единое для L1–L4):** чистая функция `session(M*, k)`, где M\* — текущий якорь, k = 1…6 — шаг цикла.
- Цикл = 6 шагов (тренировок) × 5 подходов.
- Подходы 1–4 (рабочие): `ceil(0.7·M*)`, `ceil(0.6·M*)`, `ceil(0.6·M*)`, `ceil(0.5·M*)` (минимум 1).
- Подход 5 — **«Максимум»** с минимумом `N_k = min(ceil(0.6·M*) + k − 1, M* + 1)`.
- **Успех** (все подходы выполнены, финальный ≥ N_k) → шаг k+1. **Провал** → повтор того же шага. **Два провала подряд** → авто-делoad: `M* := floor(0.9·M*)` (мин. 1).
- **Конец цикла** (6 успешных шагов): `M*' = лучший результат подхода 5 за цикл (не ниже M* − 1)`; следующий цикл от M\*'. Пересечение границы уровня → повышение метки.
- **Формальный ретест** каждые 2 цикла (≈4 недели при 3 тренировках/нед) → новый якорь. Ретест также после перерыва >2 недель.

Эталонные значения генератора: M\*=3 → рабочие 3,2,2,2, финальные минимумы 2,3,4,4,4,4; M\*=7 → 5,5,5,4 / 5,6,7,8,8,8; M\*=15 → 11,9,9,8 / 9,10,11,12,13,14; M\*=25 → 18,15,15,13 / 15,16,17,18,19,20.

**Частота и отдых:** 3 тренировки/нед на непоследовательные дни (пн/ср/пт или выбор пользователя), минимум 48 ч между тренировками. Опция «2 р/нед» — валидна (рекомендуется для L4 при застревании). Отдых между подходами: дефолт **3 мин**, пресеты 90 с и 5 мин.

**Сознательно исключено (по З1):** Armstrong, Recon Ron, GTG (несовместимы с 2–3 р/нед), rest-pause (нет данных на подтягиваниях), восходящие лесенки (нет исследований), RPE-шкала как интерфейс (новички оценивают RIR неточно — только объективный гейт «выполнил/не выполнил»).

### 3.3 Онбординг

1. Первый запуск: краткий экран «что это и как работает» → входной тест максимума (минимум 1) → рекомендация стартового шага встроенной программы (с объяснением правила).
2. Пользователь принимает рекомендацию или указывает свой максимум повторно.
3. Если пользователь не может подтянуться ни разу — отдельное сообщение: приложение пока не подходит; вернуться после первого подтягивания.

### 3.4 Экран тренировки

- Пошаговый режим: крупно номер подхода и целевое значение; список всех подходов тренировки виден рядом/снизу. Активная программа использует типы «повторения» и «максимум» (§3.1).
- Отметка выполнения подхода одним тапом; автопереход к следующему.
- Если подход не выполнен полностью — ввод фактического значения; тренировка помечается **провалом** (`result: "fail"`, частичность видна по `done < planned`, §3.9.2). Пропуск любого подхода = провал.
- **Таймер отдыха:**
  - автостарт после отметки подхода (вкл/выкл в настройках);
  - дефолт 3 мин, пресеты 90 с / 5 мин, настраивается; быстрые кнопки ±15 с; пауза/сброс;
  - окончание: **вибрация + системное уведомление** (звука нет, см. §2.7). Оставшееся время и уведомление видимы при свёрнутом приложении.
  - Техническая оговорка: `navigator.vibrate` не поддерживается iOS Safari — там только уведомление.
- Прогресс-бар тренировки, таймер общей длительности.
- Действия: пропустить подход, перенести тренировку, отменить и выйти. Незавершённая/прерванная тренировка фиксируется как **провал** → тот же шаг повторяется в следующий раз.
- Завершение: итог (объём, сравнение с планом), запись в историю, экран результата.
- Предупреждение при выходе во время активной тренировки.

### 3.5 Календарь

- Месячная сетка: плановые тренировочные дни активной программы, выполненные (ok-цвет), пропущенные/прошедшие без выполнения (нейтрально, не красным — см. «UI без чувства вины»), дни отдыха, будущие дни.
- Навигация по месяцам, «сегодня».
- Действия: начать тренировку дня, повторить пропущенную, посмотреть историю дня.
- **Перенос тренировки:** любую тренировку можно перенести на несколько дней раньше или позже — в пределах окна между предыдущей и следующей тренировкой, но **не ранее чем через 48 ч после предыдущей тренировки** (правило восстановления). **Все последующие тренировки сдвигаются на ту же дельту.**
- **Пропуск тренировки — автосдвиг (подтверждено З1):** пропуск не создаёт «долга» и не продвигает программу: пропущенный шаг остаётся следующим к выполнению (доступен через «повторить пропущенную»), а даты всех последующих плановых слотов сдвигаются вперёд на дельту пропуска с сохранением обычных интервалов. Шаги не теряются и не пропускаются. Пропуск — ни успех, ни провал; единственный гейт прогрессии — факт выполнения.
- **Правила возврата:** пропуск ≤2 недель — возврат на тот же шаг без корректировки (сила сохраняется до 3 недель). Перерыв >2 недель — предложить ретест максимума (или авто-снижение якоря на ~10%) вместо выполнения просроченного шага со старыми целями.
- **UI без чувства вины:** пропущенные дни отмечать нейтрально, «просроченные» — не красным (вина коррелирует с худшими исходами). Стрик считать по неделям и не сбрасывать при 1 пропуске.
- «Пропуск шага» — только ручное действие пользователя, не автоматический дефолт.

### 3.6 Статистика

- График «максимум повторений по датам» (тесты и лучшие подходы).
- Объём за тренировку и за неделю (сумма повторений), график.
- Стрик (серия недель без пропусков; не сбрасывается при 1 пропуске, см. §3.5), лучшие результаты.
- История всех тренировок: список с фильтром по дате (история глобальна, не привязана к программам).
- **Экспорт истории:** выгрузка всей истории тренировок со всей метаинформацией в файл (JSON), например для передачи ИИ. Требование: файл должен легко обрабатываться сторонними агентами — самодокументируемая стабильная схема (документированные поля, ISO-даты, плоская структура, без внутренних ID-ссылок). Схема зафиксирована в §3.9.2 (З3, решена).

### 3.7 Напоминания — исключено из v1

Локальные напоминания по дням недели нереализуемы в статическом PWA без внешнего push-сервиса (Web Push требует сервера; Notification Triggers API не поддерживается Safari). Исключено из v1 — см. §8. (Решение вычитки 2026-08-15.)

### 3.8 Настройки

- Таймер отдыха: дефолт, автостарт вкл/выкл, вибрация/уведомление.
- Тема: 14 цветовых тем (палитры P01–P14, см. §5.1). Внутри каждой темы — светлый и тёмный режим. Переключатели: палитра (P01–P14) + режим (светлый / тёмный / системный — по `prefers-color-scheme`). По умолчанию: P01 Volt + системный режим. Выбор сохраняется в настройках.
- Язык: EN (по умолчанию) / RU.
- Экспорт/импорт полного бэкапа всех данных (JSON), сброс данных с подтверждением.
- О приложении: версия, ссылки на первоисточники программы, **ссылка на страницу научного обоснования** (§3.10).

### 3.9 Данные и целостность (З3, решена 2026-08-15)

#### 3.9.1 Хранилище (IndexedDB)

| Таблица | Содержимое | Ключ |
|---|---|---|
| `settings` | тема (палитра + режим), таймер отдыха, язык | синглтон |
| `activeProgress` | прогресс встроенной программы: состояние, расписание | синглтон |
| `workoutRecords` | глобальная история тренировок (форма записи — §3.9.2) | внутренний автоинкремент |
| `appMeta` | версия seed встроенной программы, версия схемы данных, версия приложения | синглтон |

**`activeProgress` (детально):**
- `state` — состояние генератора §3.2.1: `anchor` (M\*), `level` (метка L1–L4), `cycleIndex`, `stepInCycle` (k), `failStreak` (0–2), `lastRetestDate`, `cycleBestMax`.
- `schedule` — упорядоченный список плановых слотов `{ date: "YYYY-MM-DD", stepRef }`, где `stepRef` — номер шага (k) в текущем цикле. Перенос тренировки и автосдвиг при пропуске (§3.5) — операции над `schedule`.
- `frequencyDays` (2 или 3) и `weekdays` (напр. mon/wed/fri).

Генератор встроенной программы — чистая функция `session(M*, k)` (§3.2.1); таблицы шагов не хранятся, хранится только состояние (anchor, k, …).

#### 3.9.2 Экспорт истории для сторонних агентов (§3.6) — `pullup-trainer-history.json`

Принципы: плоская структура (массив самодостаточных записей), **без внутренних ID-ссылок** — программа описывается значениями, а не ссылкой; все даты ISO 8601 (день — `YYYY-MM-DD`, момент — полный с offset); `schemaVersion` — целое, повышается при ломающих изменениях; читатель обязан игнорировать неизвестные поля.

```json
{
  "format": "pullup-trainer.history",
  "schemaVersion": 1,
  "generatedAt": "2026-08-15T12:00:00+03:00",
  "appVersion": "1.0.0",
  "language": "en",
  "records": [
    {
      "date": "2026-08-14",
      "startedAt": "2026-08-14T18:02:11+03:00",
      "finishedAt": "2026-08-14T18:26:45+03:00",
      "durationSeconds": 1474,
      "kind": "workout",
      "program": "builtin",
      "programName": "Pull-up Trainer",
      "context": { "level": "L2", "anchor": 7, "cycleIndex": 2, "stepInCycle": 3 },
      "result": "success",
      "sets": [
        { "position": 1, "type": "reps", "unit": "reps", "planned": 5, "done": 5 },
        { "position": 2, "type": "reps", "unit": "reps", "planned": 5, "done": 5 },
        { "position": 3, "type": "reps", "unit": "reps", "planned": 5, "done": 5 },
        { "position": 4, "type": "reps", "unit": "reps", "planned": 4, "done": 4 },
        { "position": 5, "type": "max", "unit": "reps", "planned": 7, "done": 8 }
      ],
      "totals": { "volumeReps": 27, "maxSetReps": 8, "holdSeconds": 0 }
    }
  ]
}
```

Легенда полей записи:

| Поле | Тип | Описание |
|---|---|---|
| `date` | string | День тренировки, `YYYY-MM-DD` (местное время) |
| `startedAt` / `finishedAt` | string | Моменты начала/конца, ISO 8601 с offset; `finishedAt` может отсутствовать при прерванной тренировке |
| `durationSeconds` | int | Длительность в секундах, ≥0 |
| `kind` | enum | `"workout"` — тренировка по программе; `"test"` — формальный ретест максимума: запись содержит один подход `{type:"max", unit:"reps", done: M}`, поле `planned` отсутствует, `context` отсутствует |
| `program` | enum | `"builtin"` для новых записей; старые экспорты могут содержать `"custom"` (legacy, только отображение) |
| `programName` | string | Отображаемое имя программы |
| `context` | object | Снимок состояния в момент тренировки: `{level, anchor, cycleIndex, stepInCycle}`. Legacy-экспорты могут содержать `{level: "P0", path0Step}` — read-only |
| `result` | enum | `"success"` — план выполнен; `"fail"` — прервана/недовыполнена (§3.4) |
| `sets[]` | array | Подходы по порядку выполнения |
| `sets[].position` | int | Номер подхода с 1 |
| `sets[].type` | enum | `"reps"` (обычные), `"max"` (максимум), `"hold"` (удержание), `"negative"` (негатив), `"assisted"` (ассист) |
| `sets[].unit` | enum | `"reps" | "seconds"` (hold/negative — секунды) |
| `sets[].planned` | number | Целевое значение; для `"max"` — минимум N_k |
| `sets[].done` | number | Фактическое значение; при провале может быть меньше `planned` |
| `totals.volumeReps` | int | Σ `done` по подходам с `unit="reps"` |
| `totals.maxSetReps` | int | Максимальное `done` по подходам с `unit="reps"` (лучший подход, включая `max`) |
| `totals.holdSeconds` | int | Σ `done` по подходам с `unit="seconds"` |

#### 3.9.3 Полный бэкап (§3.8) — `pullup-trainer-backup.json`

Надмножество экспорта истории: `format: "pullup-trainer.backup"`, `schemaVersion` (2), `exportedAt`, `appVersion` + объекты `settings`, `activeProgress`, `history` (записи в той же форме §3.9.2). Импорт бэкапа — полная замена состояния с подтверждением. Импорт `schemaVersion` 1 (legacy): поле `customPrograms` игнорируется; `activeProgress` с `source: "custom"` не восстанавливается (→ онбординг).

#### 3.9.4 Целостность

- Автосохранение при каждом изменении состояния (без кнопки «Сохранить», §4 п.6).
- Экспорт истории (§3.9.2) не содержит настроек и прогресса — только тренировки.
- Миграции схемы IndexedDB по версиям при обновлении приложения; seed встроенной программы версионируется в `appMeta`.
- Импорт: валидация `format`/`schemaVersion`; поддержка чтения старых `schemaVersion` — обратная совместимость.

### 3.10 Научное обоснование (страница «Почему программа такая»)

Информационная страница в приложении, объясняющая устройство встроенной программы. Цель — научная прозрачность: пользователь видит, что программа не «маркетинг», а синтез открытой научной литературы.

**Доступность:** вход со страницы «О приложении» (§3.8). Локализация: EN + RU. Страница полностью статична (текст в i18n-словарях или отдельный контент-модуль), не требует сети.

**Обязательное содержимое:**
1. **Честный заголовок-вывод**: прямых рандомизированных исследований именно схем прогрессии в подтягиваниях не существует; программа — синтез из непрямой доказательной базы (частота, объём, отдых, близость к отказу, авторегуляция). Это открыто признаётся. Приложение рассчитано на пользователей, способных выполнить хотя бы одно строгое подтягивание.
2. **Исследования и работы, на которые опирается программа**, сгруппированные по решениям схемы:
   - частота 3 р/нед и ≥48 ч отдыха (верх тела: высокая частота лучше; восстановление ~2 суток);
   - объём 5 подходов × 3 тренировки = 15 сетов/нед (доза-ответ, оптимум 10–20);
   - рабочие подходы субмаксимальные, финальный «Максимум» — один подход у отказа (обоснование из работ по близости к отказу и остановке сета по скорости);
   - дефолт отдыха 3 мин (пресеты 90 с / 5 мин);
   - повтор шага при провале, делoad −10% после 2 провалов (авторегуляция не хуже фиксированной, делoad безопасен);
   - ретест каждые 2 цикла (≈4 недели при 3×/нед) — тест не искажает прогресс;
   - автосдвиг при пропуске и возврат ≤2 недель (сила сохраняется до ~3 недель; гибкое расписание формирует более прочные привычки).
3. **Все формулы схемы** (§3.2.1), выведенные явно, с примером подстановки чисел и с указанием, каким источником обоснован каждый параметр. Полный список формул:
   - уровни по тесту M: 1–4 / 5–9 / 10–19 / 20+ (минимум M=1);
   - рабочие подходы: `ceil(0.7·M*)`, `ceil(0.6·M*)`, `ceil(0.6·M*)`, `ceil(0.5·M*)`, минимум 1;
   - финальный минимум: `N_k = min(ceil(0.6·M*) + k − 1, M* + 1)`;
   - делoad: `M* := floor(0.9·M*)`, минимум 1;
   - конец цикла: `M*' = max(лучший результат подхода 5 за цикл, M* − 1)`;
   - частота/длины: цикл 6 шагов, ретест каждые 2 цикла (≈4 недели при 3×/нед).
4. **Список источников** со ссылками, журналом и годом. **Только открытые источники**: open-access полнотексты (Frontiers, PMC, MDPI, Springer OA, Sci Rep и т.п.) и/или публичные аннотации PubMed. Работы за пейволлом в приложение не включаются. Базовый список — из `research/research-pullup-program-science-2026-08-15.md` (там 53 источника, отбирается открытое подмножество).
5. Пометки честности: что является экстраполяцией (перенос данных с жима/тяги на подтягивания; протокол «N субмаксимальных + финальный AMRAP» как целое не тестировался), что — одиночным источником (препринты), а что подтверждено несколькими независимыми работами.

**Требования к оформлению:** тот же дизайн-язык Poster / Swiss; формулы — читаемым текстом/HTML-математикой (без внешних библиотек); ссылки — обычные `<a>` (кликабельны при наличии сети, текст остаётся полностью читаемым офлайн).

### 3.11 Экран установки PWA (обязательный)

Если приложение открыто как обычная вкладка браузера (не установлено как PWA) — пользователю **обязательно** показывается экран с подробной визуальной инструкцией по установке.

**Детекция «не установлено»:** приложение считается установленным, если `window.matchMedia('(display-mode: standalone)').matches` ИЛИ `navigator.standalone === true` (iOS Safari). Всё остальное (вкладка, minimal-ui, встроенный webview с поддерживаемой детекцией) = не установлено → показывать экран.

**Поведение:**
1. Экран показывается при каждом запуске приложения, пока оно не установлено. Полноэкранный modal поверх интерфейса; закрываемый (пользователь может пользоваться приложением), но появляется снова при следующем запуске. После установки (детекция «установлено») — больше не показывается.
2. Автоопределение платформы по User-Agent: iOS Safari, Android (Chrome и др. Chromium-браузеры), десктоп (Chrome/Edge). **Инструкция выбранной платформы — по умолчанию**; остальные доступны вкладками.
3. Каждая инструкция — пошаговая, визуальная: нумерованные шаги + наглядные изображения (стилизованные SVG-диаграммы в духе Poster / Swiss; скриншоты реальных браузеров не обязательны).
   - **iOS Safari:** Share → «На экран „Домой“» → подтвердить. Пометить: поддержка — Safari, другие браузеры iOS не умеют.
   - **Android Chrome:** меню ⋮ → «Установить приложение» / «Добавить на главный экран»; при наличии `beforeinstallprompt` — прямая кнопка «Install» на экране.
   - **Десктоп Chrome/Edge:** иконка установки в адресной строке (или меню → «Установить…»).
   - **Прочие/неизвестные:** общая инструкция (искать пункт «Добавить на главный экран / Установить» в меню браузера).
4. Везде, где платформа поддерживает `beforeinstallprompt` (Chromium) — кнопка установки прямо на экране; на iOS — только инструкция.
5. Требования к платформе установки не выполняются (например, сайт не прошёл критерии installability) — экран всё равно показывается с инструкцией (шаги остаются верными: критерии выполняет наш манифест; на время разработки/отладки допускается служебная пометка).
6. Локализация: EN + RU. Тот же дизайн-язык; тач-цели ≥44px.

## 4. Нефункциональные требования

1. **PWA:** манифест (имя, иконки, тема, display: standalone), service worker с кэшированием ассетов (app-shell) и офлайн-доступом; приложение открывается без сети после первого визита. Учесть базовый путь (subpath) для GitHub Pages.
2. **Офлайн-first:** все операции работают без сети; серверных зависимостей нет (статический хостинг GitHub Pages).
3. **Поддержка:** современные Chrome, Safari (iOS), Firefox, Edge. Мобильные браузеры — приоритет; десктоп — работает корректно без специальных удобств.
4. **Производительность:** старт ≤2 с на среднестатистическом телефоне (после кэширования — мгновенно); анимации 60 fps.
5. **Доступность:** контраст, крупные тач-цели (≥44 px), управление с клавиатуры, `prefers-reduced-motion`.
6. **Надёжность:** автосохранение без кнопки «Сохранить»; состояние не теряется при закрытии вкладки.
7. **Безопасность:** нет внешних сервисов, трекеров и сбора данных (local-first = privacy-first; пункт маркетинга).

#### 5.1.1 Реализация UI

- **База: голый CSS + токены, без CSS-фреймворков и компонентных библиотек.** Компоненты — Vue SFC со scoped-стилями; общий слой — reset, типографика (Arial Black / mono / sans), классы-паттерны (`.kicker`, `.panel`, `.btn`, `.tabbar`); все цвета — только из переменных `design/theme-tokens.css`. SVG-графики и кольцо таймера — инлайн-SVG, как в мокапах.
- Обоснование: токены и компонентная спецификация уже готовы (§5.1), для ~15 компонентов нет окупаемости Tailwind/компонентных библиотек, а постерная эстетика (офсет-тени, рамки 2px, плашки) не выражается утилитами. Плюс: минимальный бандл для PWA-бюджета (≤2 с старт), ноль рантайм-зависимостей сверх Vue/Pinia, соответствие дизайн-языку Poster/Swiss (§5.1.2).
- **Исключение — не «городить» уже существующее.** Если возникает потребность в нетривиальной функциональности, которую уже решают готовые инструменты (например, headless-примитивы с ARIA и focus trap для bottom sheet/dialog — Reka UI, выбор дат, drag-календарь и т.п.), предпочтительно взять точечный внешний инструмент (headless/unstyled, чтобы темизировать токенами), а не переписывать его самостоятельно. Полные компонентные библиотеки по-прежнему не берём.
- Переключение темы: Pinia-стора настроек пишет `data-theme="<slug>-<mode>"` на `<html>`; режим `system` резолвится через `prefers-color-scheme`.

#### 5.1.2 Мокапы и UI-аудит

HTML-мокапы в `design/mockups/` — **референс стиля и дизайн-идеи**, а не точная карта экранов приложения. В реализации и при аудите UI **не требуется** pixel-perfect повторение layout, текстов, KPI-подписей, overlay-паттернов и прочих второстепенных деталей мокапа.

**Приоритеты при реализации и UI-аудите (по убыванию):**
1. Логичность интерфейса, удобство, UX, соответствие продуктовым сценариям (этот документ, §3).
2. Доступность (контраст, тач-цели, клавиатура, screen reader).
3. Общий визуальный характер Poster/Swiss: токены, типографика, паттерны из `design/poster-design.md`.
4. «Ощущение» мокапов — цвета, плашки, тени, масштаб типографики — без чеклиста расхождений по каждому элементу.

Сверка с мокапами допустима для sanity-check стиля; расхождения с мокапом **не являются дефектом**, если интерфейс понятен, удобен и соответствует дизайн-системе.
