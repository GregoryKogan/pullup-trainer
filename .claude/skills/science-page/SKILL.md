# Страница «Почему программа такая»

Самая дисциплинированная часть проекта: текст здесь связан с кодом машинной проверкой.
Правка «на глаз» ломает сборку.

## Файлы

- `src/i18n/locales/science/en.json` и `ru.json` — копия, 34 листовых ключа, структура один в один.
- `src/views/WhyProgramView.vue` — рендер.
- `scripts/audit-science-crosswalk.mjs` — аудит (`npm run audit:science`).
- `e2e/science.spec.ts` — проверяет заголовки секций и примеры формул в обоих языках.

## Структура локали

```
title, introTitle, intro[]
sections.{overview, levels, algorithm, progression, frequency, volume,
          workingSets, finalMax, rest, skips, rejected, limitations}
   → каждая { title, body[] }
formulas.title, formulas.items[]   → ровно 6 штук, { formula, example, note? }
badges.{confirmed, single, extrapolation}
sourcesTitle, sources[]            → { id, badge, url, ... }
```

**12 секций и ровно 6 формул** — это жёсткая проверка в аудите. Добавить секцию можно только
вместе с правкой `requiredSections` в скрипте и списков заголовков в `e2e/science.spec.ts`
(там оба языка).

## Правила цитирования

Ссылка в тексте — `[N]`, где N совпадает с `id` в `sources[]`. Аудит требует **биекцию**:

- каждый источник процитирован хотя бы раз в `intro`, `sections.*.body` или `formulas.items`;
- каждая цитата `[N]` имеет запись в `sources[]`.

Осиротевший источник и висячая цитата одинаково роняют аудит. Цитаты собираются только из EN —
но ключи, `id`, `url` и `badge` обязаны совпадать с RU.

### Бейджи доказательности

| Бейдж | Когда |
|---|---|
| `confirmed` | воспроизведено в нескольких исследованиях |
| `single` | одно исследование |
| `extrapolation` | перенос с другого упражнения (жим, тяга верхнего блока, присед) |

Другие значения запрещены. `extrapolation` обязателен, когда данные не про подтягивания —
это продуктовое требование про честность, а не формальность.

`url` обязан начинаться с `https://` и вести на **открытый** источник: open-access полнотекст
или аннотация PubMed. Пейволы не годятся.

## Формулы дублируют код

Аудит независимо реализует генератор и сверяет с эталонными таблицами M\*=3/7/15/25, а также
проверяет буквальные подстроки в примерах:

- `M*=7 → 5,5,5,4`
- `N_1…N_6 = 5,6,7,8,8,8`

Плюс `levelFromM(7) === 'L2'`, `deloadAnchor(7) === 6`, `deloadAnchor(3) === 2`.

**Меняешь формулу в `src/domain/` — обязан обновить и `scripts/audit-science-crosswalk.mjs`,
и примеры в обеих science-локалях.** Аудит специально устроен как независимая реализация:
он ловит расхождение кода и текста, поэтому «поправить только скрипт, чтобы прошло» —
неправильный ход.

## Порядок правки

1. Правишь EN, зеркалишь RU (ключи один в один).
2. Новое утверждение → новый источник в `sources[]` обоих языков с одинаковыми `id`/`url`/`badge`.
3. `npm run audit:science`
4. Менял заголовки секций или примеры формул → обнови `e2e/science.spec.ts` и прогони
   `npm run test:e2e -- science`.
5. Русский текст перед коммитом прогони через скил `humanizer-ru`, английский — через `humanizer`.
